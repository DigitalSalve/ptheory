# multi-env scaffolding

Copy these files into a new project to implement the Render multi-environment template pattern.

## File layout after copying

```
<project-root>/
├── render.yaml.template
├── render.yaml                          ← generated by CI, do not hand-edit
├── .gitattributes                       ← must contain: render.yaml merge=ours
└── .github/
    ├── env-values/
    │   ├── production.env
    │   └── staging.env
    └── workflows/
        └── generate-render-yaml.yml
```

## Setup checklist

- [ ] Copy all files to project root
- [ ] Replace `myapp` prefix in `render.yaml.template` with your service name prefix
- [ ] Remove unused service types (worker, web, webapp, database) from template
- [ ] Update `PROJECT_NAME` in both `.env` files to match your Render project name
- [ ] Append `gitattributes-snippet` content to project's `.gitattributes`
- [ ] Delete `gitattributes-snippet` after appending
- [ ] Create matching env groups in Render dashboard (names == `PROJECT_NAME`)
- [ ] Attach env groups to their environment's services in Render
- [ ] Add secrets + URLs to env groups (JWT_SECRET, STRIPE_*, API URLs, etc.)
- [ ] Delete old `render.yaml` (will be regenerated by CI)
- [ ] Locally verify: `envsubst '$PROJECT_NAME $ENV_NAME $BRANCH_NAME' < render.yaml.template > render.yaml`
- [ ] Push to staging branch first, verify services remain healthy
- [ ] Promote to main via normal PR

## What goes where

**In the Blueprint template (`render.yaml.template`):**
- Service structure (names, runtime, buildCommand, startCommand)
- `NODE_ENV` (literal per environment)
- `DATABASE_URL` (via `fromDatabase`)
- `INTERNAL_API_URL` (via `fromService` + `hostport`)
- `fromGroup: ${PROJECT_NAME}` reference

**In Render env groups (per environment):**
- All secrets (JWT_SECRET, STRIPE_SECRET_KEY, AWS_*, etc.)
- All public URLs (API_BASE_URL, NEXT_PUBLIC_API_URL, BASE_URL, etc.)
- All API keys (SENDGRID_*, third-party services)
- App-level config (feature flags, bucket names, etc.)

**Never in either (Render auto-provides):**
- `PORT` (assigned by Render)
- Service IDs
